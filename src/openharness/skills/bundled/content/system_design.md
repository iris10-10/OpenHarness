# 系统设计问答技能

以标准面试流程引导用户完成系统设计题：需求澄清 → 容量估算 → 高层设计 → 深入设计 → 权衡总结。既可用于面试练习（分步引导、用户先答），也可用于讲解经典题。

## 何时使用

- 用户提到系统设计面试 / 设计题（秒杀、短链、Feed 流、IM 等）
- 用户问"系统设计该怎么准备 / 有什么框架"
- 用户想演练一道系统设计题并被打分
- 用户纠结某道设计题的标准思路

## 引导流程（面试练习模式，分步引导）

**规则：每一步先让用户给出自己的方案，再点评补充；不要一次性倒出完整答案。**

1. **需求澄清（3-5 分钟）**：引导用户先问功能需求（核心用例、边界）与非功能需求（QPS、延迟、一致性、可用性）。面试官视角：主动澄清需求是加分项。
2. **容量估算**：DAU → 读写 QPS → 存储 / 带宽 / 缓存容量（公式见下）。让用户自己算，检查数量级是否合理。
3. **API 与数据模型**：核心接口定义 + 存储选型（选 SQL / NoSQL 的理由，用户要能说出 trade-off）。
4. **高层架构**：画组件框图（网关、服务、缓存、MQ、存储），说明请求链路。
5. **深入设计**：围绕该题的核心难点深入 1-2 个组件（如秒杀的库存扣减、短链的 ID 生成），这一步决定面试档位。
6. **权衡讨论**：CAP 取舍、单点故障、扩展瓶颈、成本；主动说"如果我再有一个月，会改进 X"。
7. **总结与评分**：按评分标准打分，输出改进点。

讲解模式下（用户直接要答案）：按上述框架完整讲解，重点展开第 5 步。

## 容量估算备忘

- QPS：DAU × 人均操作次数 ÷ 86400 × 峰值系数（×3-5）；读写分离场景分别估算
- 存储：每日新增条目 × 单条大小 × 副本数 × 增长期（如 5 年）
- 缓存：热数据遵循 80/20，容量 ≈ 20% 热数据的 1.5 倍
- 带宽：QPS × 平均响应大小（含放大系数）
- 常见量级：单机 MySQL 约 1-5k QPS、Redis 单机 10w QPS、千兆带宽 ≈ 100MB/s

## 经典题速查（核心要点内联）

| 题目 | 核心难点 | 关键组件/方案 |
|------|---------|--------------|
| 短链接系统 | ID 生成与冲突 | 发号器（号段模式/雪花 ID）+ 布隆过滤器判重；302 跳转 + 缓存热点；读多写少可全量缓存 |
| 秒杀系统 | 突发流量与库存超卖 | 多级限流（网关/令牌桶）、库存预扣（Redis Lua 原子扣减）、MQ 异步下单、库存分段 |
| 新闻 Feed 流 | 推拉模型选择 | 推模式（写扩散，适合普通用户）vs 拉模式（读扩散，适合大 V）；混合：大 V 拉普通人推；Feed 排序召回链路 |
| 即时通讯 IM | 连接管理与消息可达 | 长连接网关（接入层）、消息 ID 去重与有序性（seq）、离线消息、已读回执、单聊群聊扇出差异 |
| 点赞/计数系统 | 高并发写 | Redis 计数 + 异步落库（合并写）、计数与业务解耦、防刷（幂等/限频） |
| 排行榜 | 实时排名 | Redis ZSet；亿级用户分桶（局部 TopN 归并）、近似排名（跳表分桶估算） |
| 分布式爬虫 | 调度与去重 | URL 去重（布隆过滤器）、优先级调度、 politeness 限速、增量抓取、断点续爬 |
| 网盘系统 | 大文件分块 | 分块上传/秒传（文件哈希）、断点续传、去重存储、CDN 下载加速 |
| 附近的人 | 地理位置索引 | GeoHash / 四叉树 / R 树；Redis GEO；范围查询与分页 |
| 分布式任务调度 | 高可用触发 | 分片广播、故障转移、一致性（数据库乐观锁/分布式锁）、幂等执行 |
| 限流器 | 算法选择 | 令牌桶 vs 漏桶 vs 滑动窗口；分布式限流（Redis Lua）与本地限流的权衡 |
| 通知系统 | 多渠道扇出 | 模板渲染、渠道适配、优先级队列、频控与合并、送达追踪 |

## 评分标准（1-5 分/维，练习模式打分用）

| 维度 | 1-2 分 | 3 分 | 4-5 分 |
|------|--------|------|--------|
| 需求澄清 | 直接开答 | 提到功能需求 | 主动澄清功能+非功能，明确边界与规模假设 |
| 容量估算 | 无估算 | 数量级正确 | 估算驱动后续选型，明确说出依据 |
| 架构设计 | 单机思维 | 组件齐全、链路清晰 | 组件选型有 trade-off，识别单点与瓶颈 |
| 深入细节 | 停留在框图 | 讲清 1 个核心组件 | 核心组件讲到数据结构与异常路径 |
| 权衡意识 | 无 | 能答"为什么" | 主动讨论 CAP/成本/演进路线，诚实承认未考虑的点 |

- **Junior 通过线**：需求澄清 + 架构设计 ≥ 3 分，其余 ≥ 2 分
- **Senior 通过线**：五维全部 ≥ 3 分，且深入细节与权衡意识 ≥ 4 分

## 行为规则

- 练习模式严格分步：用户答完一步再给反馈进入下一步；一次只抛一个问题
- 点评先肯定对的点，再指出问题，最后给参考方案
- 评分诚实：达到什么水平说什么水平，不虚高
- 讲解标注"这是通用参考方案"，具体实现因公司业务规模而异
