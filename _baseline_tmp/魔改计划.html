Phase 1 — RAG 基础设施

优先级：最高
向量数据库集成
src/openharness/rag/vectorstore.py
新增
引入 ChromaDB 作为本地向量数据库，支持持久化存储和高效相似性检索。
  • ChromaDB 本地持久化，数据存储在 ~/.openharness/chromadb/
  • 多 Collection 管理：jobs、resumes、interview、companies、skills
  • 支持增删改查与元数据过滤
  • 降级方案：FAISS 离线索引备用
chromadb rag/vectorstore.py
Embedding 服务
src/openharness/rag/embedding.py
新增
多策略文本向量化服务，支持在线和本地两种模式。
  • 在线：OpenAI text-embedding-3-small / 阿里千问 Embedding
  • 本地：sentence-transformers (BGE-M3) 离线模型
  • 自动降级：在线不可用时切换本地模型
  • 缓存层：避免重复 Embedding 调用
sentence-transformers rag/embedding.py
文档分块与摄入管道
src/openharness/rag/ingestion.py
新增
面向求职场景的文档分块和摄入流水线。
  • 智能分块：按语义段落切分，保持上下文完整
  • 多格式解析：PDF、Markdown、JSON、HTML
  • 元数据标记：来源、类型(岗位/简历/面经)、日期
  • 增量更新：仅处理新增/变更文档
pypdf beautifulsoup4 rag/ingestion.py
检索与重排序器
src/openharness/rag/retriever.py
新增
两阶段检索：向量召回 + 精排序。
  • 阶段一：向量相似度 top-K 召回 (cosine)
  • 阶段二：LLM-based 重排序，结合元数据权重
  • 混合检索：关键词 BM25 + 向量语义融合
  • 上下文窗口控制：token 预算内最优选择
rag/retriever.py
RAG 检索工具
src/openharness/tools/rag_search_tool.py
新增
将 RAG 检索能力注册为 Agent 可调用的工具。
  • rag_search：语义搜索知识库
  • rag_search_jobs：搜索匹配岗位
  • rag_search_interview：搜索面经题目
  • 继承 BaseTool，纳入权限系统和工具注册器
tools/rag_search_tool.py tools/__init__.py
RAG 上下文注入
src/openharness/prompts/context.py (修改)
修改
在运行时系统提示词组装中注入 RAG 检索结果。
  • 在 build_runtime_system_prompt() 中新增 RAG 段
  • 根据用户 query 自动检索相关知识
  • token 预算控制，不挤占核心上下文
  • 与现有记忆系统协同（RAG 精确检索 + 记忆模糊关联）
prompts/context.py

Phase 2 — 求职专用工具集

优先级：高
简历管理工具
tools/resume_tool.py
新增
完整的简历解析、存储、生成和优化能力。
  • resume_parse：解析 PDF/Markdown 简历，结构化提取
  • resume_generate：根据岗位 JD 定向生成简历
  • resume_optimize：基于 ATS 友好度评分优化
  • resume_compare：多版本简历对比分析
  • 结构化存储到 RAG 向量库，支持语义检索
tools/resume_tool.py rag/vectorstore.py
岗位匹配引擎
tools/job_match_tool.py
新增
基于语义相似度的岗位-简历双向匹配。
  • job_match：简历 → 匹配岗位列表 (Top-K)
  • candidate_match：岗位 → 匹配候选人 (反向)
  • 匹配维度：技能、经验、学历、项目、软技能
  • 匹配度评分 + 差距分析报告
  • 支持时间衰减（新鲜岗位权重更高）
tools/job_match_tool.py rag/retriever.py
面试准备系统
tools/interview_tool.py
新增
基于目标岗位的面试题目生成与练习。
  • interview_questions：根据 JD 生成高频面试题
  • interview_practice：模拟面试，实时评分
  • interview_feedback：回答质量分析与改进建议
  • 题型覆盖：八股、算法、系统设计、项目深挖
  • 关联牛客/力扣面经库，真实题目优先
tools/interview_tool.py

tools/salary_tool.py

  • salary_negotiate：薪资谈判话术与策略生成
  • 数据源：公开招聘薪资 + 历史投递记录
  • 总包计算：base + bonus + stock 年化
tools/salary_tool.py

向量检索 jobs Collection

job_match (简历↔岗位)
skill_gap_analyze

注意事项与风险

爬虫合规性
风险
  • 遵守目标网站 robots.txt 和 ToS
  • 请求频率控制在合理范围
  • 仅采集公开信息，不存储个人隐私
  • 考虑使用官方 API 替代爬虫
Embedding 成本
风险
  • 在线 Embedding 有 API 调用费用
  • 大批量摄入建议使用本地模型
  • 缓存层避免重复计算
  • 增量更新策略减少全量重建
上下文 Token 预算
风险
  • RAG 注入内容占用上下文窗口
  • 设置硬上限（不超过 25%）
  • 与现有压缩系统 (compact) 协同
  • 检索结果摘要化，不全量注入
隐私数据保护
风险
  • 简历含个人信息（姓名/电话/邮箱）
  • 向量库存储需脱敏或加密
  • 不将隐私数据发送到外部 API
  • 本地优先：ChromaDB + 本地 Embedding
改造总结： 本方案以 最小侵入 为原则，复用 OpenHarness 的 Agent Loop、工具注册、权限检查、多 Provider、记忆系统等成熟基础设施，仅在三个层面进行扩展：

1. 知识层 — 新增 RAG 模块（向量库 + Embedding + 检索器），赋予 Agent 领域知识检索能力
2. 工具层 — 新增 12+ 求职专用工具（简历/岗位/面试/薪资/公司/投递等），覆盖求职全流程
3. 提示词层 — 修改系统提示词和上下文组装，注入求职领域知识和 RAG 检索结果

改造后的 Agent 能够：理解用户求职意图 → 检索知识库 → 调用专用工具 → 生成结构化建议 → 持续追踪进度。
