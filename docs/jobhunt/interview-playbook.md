# OpenHarness 项目面试准备稿

这份材料用于面试前复习和现场演示。回答应以真实实现为准，不把规划中的功能描述成已经上线的功能。

## 30 秒介绍

我做的是一个本地优先的求职 Agent。它把简历解析、岗位检索、岗位匹配、面试练习和投递追踪串成一条流程。底层复用了 OpenHarness 的 Agent Loop、工具注册、权限控制、RAG 和本地记忆能力；求职领域层负责 JD/简历结构化解析、匹配评分、面试题选择和回答反馈。面试准备模块支持按岗位、公司、轮次和难度生成题目，用户可以逐题作答，系统会持久化会话并给出可复盘的评分报告。

## 2 分钟介绍结构

1. **背景**：求职材料、岗位要求和面经通常分散，准备过程难以追踪。
2. **目标**：把“找到岗位 → 分析匹配度 → 准备面试 → 复盘投递”统一到一个本地优先系统中。
3. **架构**：
   - Web/CLI 作为入口；
   - 工具层连接简历、岗位、面试和投递能力；
   - 领域层负责解析、评分、题目选择和 JSON 持久化；
   - RAG 层存储岗位、简历和面经，并提供召回、关键词检索和重排；
   - OpenHarness 核心层提供 Agent Loop、工具调用、权限和上下文管理。
4. **面试闭环**：
   - `POST /api/interview/practice` 创建会话；
   - `POST /api/interview/sessions/{id}/answer` 逐题评分并推进题号；
   - `GET /api/interview/sessions` 查看历史；
   - `POST /api/interview/sessions/{id}/finish` 提前结束并生成报告。
5. **设计取舍**：
   - 真实面经优先，JD 技能题库其次，通用题库兜底；
   - 评分使用可测试的确定性规则，模型负责把结构化结果转成自然语言；
   - 数据优先保存在本地，减少简历和回答泄露风险；
   - 回答提交带题号校验，防止浏览器重复提交覆盖会话进度。
6. **边界**：当前评分是训练反馈，不是招聘结论；外部岗位源和模型服务不可用时，仍可用本地题库和示例数据完成离线演示。

## 高频追问

### 为什么面试题不是全部交给模型生成？

题目选择使用确定性题库和 RAG 召回，便于测试、复现和离线运行。模型可以负责补充解释、追问和报告润色，但核心题目来源和评分结果不会因为一次模型采样完全改变。

### 面经和题库如何组合？

先按公司、岗位和技能检索 `interview` 集合中的真实面经，再用 JD 技能映射到内置题库。如果 RAG 不可用或没有结果，就返回题库题目并给出提示，不让整个练习流程失败。

### 如何防止重复提交同一道题？

服务端从会话的 `current_index` 读取当前题目。客户端提交 `question_index` 时，服务端检查它是否等于当前题号；不一致就返回 `409`，不会重复写入评分记录。

### 为什么答案评分要持久化？

评分记录包含题号、回答、总分、分维度建议和缺失关键词。这样用户可以在下一次练习前查看薄弱点，也能把一次模拟面试复盘成可执行的练习计划。

### 如果用户中途退出怎么办？

会话状态和当前题号写入本地 JSON，重新打开历史会话即可继续未完成题目；用户也可以主动结束，系统会保留已经回答的部分并生成阶段性报告。

### 为什么使用本地 JSON，而不是一开始接数据库？

项目定位是本地优先，求职数据包含简历和面试回答。当前数据量和单用户场景适合原子写入加锁的 JSON 存储，部署成本低；如果进入多用户生产环境，再替换为数据库和用户隔离层。

### 如何扩展新的面试轮次？

在 `questions.py` 中增加轮次到题型的映射和指导语，在评分器中增加对应维度或规则，再通过工具层和 API 暴露。领域层不依赖 FastAPI，便于单元测试。

## 现场演示脚本

1. 启动 Web UI，打开“面试准备”。
2. 填入公司、岗位、JD、轮次和题目数量。
3. 创建模拟面试，展示第一道题和当前进度。
4. 输入一段按“结论 → 原理 → 实践 → 权衡”组织的回答。
5. 提交后展示分维度评分、缺失关键词和下一题。
6. 完成或提前结束，展示平均分、完成度和逐题复盘。
7. 刷新页面或重新选择历史记录，证明会话已经持久化。
